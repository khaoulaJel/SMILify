## The goal (do not lose this)

Can a learned neural network produce a better SMILify pose initialization
than zero-init, and *why*? This is being pursued to paper-worthy rigor: every
claim needs a controlled comparison against the project's own established
metrics (leg_acc, all_feature_R via `run_audit.py`/`calib_features.py`,
Chamfer/F-score via `eval_run.py`), every hypothesis gets tested empirically
rather than just proposed, and every negative result is reported honestly
rather than reframed.

## How we got here (compressed; full detail in CHAIN_OF_THOUGHT file)

1. Fixed real bugs before training anything: a topology mismatch (wrong
   `.pkl` model used to generate the training corpus, root-caused to
   `config.py`'s import-time env-var resolution) and an axis-angle vs.
   rotation-matrix bug in the training script.
2. Ran arms A (zero-init) / B (cheap analytic init) / C (learned init)
   against the project's real metrics — corrected an early misreading where
   23.1° had been mistaken for "best existing initializer" when it was
   actually zero-init's own error.
3. Ran a mechanistic D (random) / E (proximal-error) / F (distal-error)
   perturbation experiment, magnitude-matched (~23°), grounded in SO(3)
   sampling literature (Kuffner 2004, Yershova & LaValle 2004). Finding:
   error *structure*, not magnitude, determines optimizer basin quality —
   proximal joint errors are far more damaging than distal ones because they
   propagate more downstream surface displacement (forward kinematics).
4. Investigated the existing correspondence-free scan-to-anatomy pipeline
   before writing new code, per explicit "investigate first" instruction.
   Found and fixed two real defects in the shared primitive
   `fitter_3d/geom_leg_init.py`: mesothoracic-leg starvation in
   `assign_points_to_legs` (old coxa-point method kept, renamed
   `assign_points_to_legs_coxa`, for auditability) and a single-point
   body-core representation. Both replaced with chain/polyline-based
   assignment (RigNet-inspired), both validated against `synth_clean` ground
   truth before being trusted (macro-F1 0.656→0.831, core_recall
   0.366→0.663).
5. Tested the resulting learned initializer on **real, unseen bench50 scan
   data** (50 real specimens, not synthetic) — genuine **negative result**:
   G1 (learned init) measurably *lost* to G3 (zero-init).
6. Investigated why. Ruled out PCA-rotation-magnitude as the explanation (no
   correlation). Confirmed a **domain-gap hypothesis**: the synthetic
   training corpus's pose-noise magnitude was much larger than real
   deployment pose-noise. Retrained at progressively lower pose-noise scales
   and re-fit bench50 each time:

   | Arm | pose_scale | vs. zero-init on real bench50 |
   |-----|-----------|-------------------------------|
   | G1  | 0.50 (original) | significantly worse |
   | G1b | 0.15 | still worse, gap narrowing |
   | G1c | 0.10 | parity |
   | G1d | 0.05 | fit completed 2026-08-21 11:51–12:07; **eval not yet run** (see below) |

   This is a clean, monotonic dose-response curve — strong evidence for the
   domain-gap explanation.

## Working style established in this investigation (keep following it)

- **Probe before editing** — read the actual data/shape/config before any
  edit that depends on it (per project `CLAUDE.md`). This caught the
  topology bug and the axis-angle bug early.
- **No same-turn cleanup of diagnostic artifacts.** Scratch scripts, probe
  outputs, comparison plots stay on disk under clear names
  (`diagnostics/`, `*_PROBE.*`) until the user has reviewed and signaled OK.
- **Fix shared primitives at the shared level, preserve old behavior for
  auditability.** `assign_points_to_legs_coxa` was kept, not deleted, when
  `assign_points_to_legs_chain` replaced it as the default — this was an
  explicit user instruction, not a style preference, because the old
  function's behavior needed to remain inspectable/reproducible.
- **Report negative results honestly, don't reframe them.** The bench50 G1
  vs G3 loss was reported as a loss, investigated for its actual cause, not
  spun. When the user caught an overclaim ("F beats gtinit" →
  "F slightly exceeds the gt-init reference on some post-fit metrics in this
  experiment"), that correction was adopted verbatim into the writeup.
- **Validate literature claims via search before trusting them**, especially
  for anything touching SO(3) sampling, forward-kinematics error
  propagation, or correspondence/assignment methods (RigNet-style nearest-
  chain-segment assignment was grounded this way).
- **Statistical rigor**: paired t-tests for per-specimen comparisons, not
  just mean deltas.
