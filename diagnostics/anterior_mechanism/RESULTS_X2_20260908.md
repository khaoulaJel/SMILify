# X2 — FAIL. The allometric prior fixes its own proxy hard, but the head-carriage mechanism moves the wrong way.

Bar fixed in `PREREGISTRATION_X2_allometric_prior.md` **before** the run. Job 3865868 (training,
killed only for a slow CPU-device cost measurement after training completed cleanly) +
job 3866148 (measurements, GPU), `bench50_clean` (50 real scans), seed 0. Arm A/B reused
verbatim from X1 (job 3350026); arm C run fresh.

---

## Verdict

> **FAIL, per §5's explicit third row: "no significant movement toward 1.0, despite the proxy
> holding."** The allometric prior clears its own positive control by a huge margin (proxy
> residual down 71% vs A, 71% vs B, both p < 1e-9) and costs essentially nothing in Chamfer
> (C/B = 1.0004×, the 1.4× cost bar is not even approached). But the head deform ratio — the
> gating endpoint — moved **away** from 1.0 (0.793 → 0.850, Δ = −0.025 against a required
> +0.05), not toward it, and the movement is not significant (sign p = 0.48).

Per §6's outcome table, this is the **decisive negative**: "proxy holds, head ratio unmoved"
narrows the search by ruling out shape-plausibility as the failure mode entirely. The defect the
objective misses is not fixed by supplying a *correct* biological target for the anterior
proportions — only by supplying a term the objective structurally cannot reach any other way,
which is what G6/G7's joint-position-term direction already showed working (11.0% vs 38.9% joint
residual, a real Pareto win). **H2 is not supported.**

## Task 1 — `w_allo` calibration

Per §3 Step 1, `w_allo` must be set so its gradient magnitude is comparable to
`w_scale · d(scale_barrier)/d(params)` at a **realistic, non-degenerate** point in training —
explicitly *not* at Stage_2's cold start, where `scale_barrier`'s gradient is exactly zero by
construction (log_beta_scales = 0 exactly, and the barrier's `clamp_min(0.0)` zeroes both value
and gradient at the boundary).

**First finding: a 75-iteration pilot (the preregistration's own initial guess) is STILL
degenerate.** `scale_barrier`'s free band is ±ln(2) ≈ ±0.693 in log-scale — wide enough that
nothing in arm A's Stage_2 loss (`w_scale=0`, `w_sym=0.5` only weakly ties L/R pairs that start
identical) pushes any joint's `log_beta_scales` past it within 75 its. Both the barrier's value
and its gradient were exactly `0.0` at that checkpoint — the same degeneracy the preregistration
flagged for `t=0`, just not resolved by the originally-suggested pilot length.

**Second finding: the first tick where the gradient crosses zero is itself a bad calibration
point.** Extending the search and checkpointing every 25 its, the gradient first goes non-zero at
it=350 (`||grad_sc|| = 1.0e-5`) — but that value is dominated by whichever single joint/specimen
entry *just* crossed the boundary, not a representative gradient magnitude. Using it gives
`w_allo = 0.052 × 1.0e-5/0.062 ≈ 8.3e-6`, a degenerate, unusably tiny weight.

**Resolution:** ran the FULL 1000-iteration Stage_2 (arm A's own pre-registered length, `w_scale=0`,
no `w_allo` term active — matches arm A exactly), checkpointing every 25 its, and used the
**last** checkpoint (it=1000, the natural end of Stage_2 / start of Stage_3, which carries the
identical loss weights) as the calibration point:

| quantity | value |
|---|---:|
| `scale_barrier(log_beta_scales)` | 0.003450 |
| `‖grad(scale_barrier)‖` (raw, w.r.t. `log_beta_scales`) | 0.001293 |
| `allometric_prior_loss` (unweighted) | 0.030672 |
| `‖grad(l_allo)‖` (raw, combined L2 over `betas`/`joint_rot`/`global_rot`/`trans`/`deform_verts`) | 0.131775 |
| per-tensor grad norms of `l_allo` | betas 0.00455, joint_rot 0.01552, global_rot 0.00064, trans 3.2e-9, deform_verts 0.13078 |
| ratio `‖grad_sc‖ / ‖grad_allo‖` | 0.009814 |
| `w_allo` raw = `0.052 × ratio` | 0.000510 |
| **`w_allo` final (2 s.f.)** | **0.00051** |

Sanity check (2 more iterations with the real weighted `w_allo=0.00051` term active): total loss
went 0.003085 → 0.003075 (no blowup), and the `allo` component itself visibly responded
(0.0307 → 0.0284) — the weighted term engages and does what it's supposed to, at a magnitude that
doesn't dominate the objective. **No bug found in the already-implemented `joint_limits.py` /
`trainer_moonshot.py` code** — `build_head_width_reporter_matrix` and `allometric_prior_loss`
behave exactly as documented; the only issues were in calibration *methodology* (pilot length),
not in the implementation.

Script: `x2_calibrate_wallo.py`. Raw output: `out_X2/wallo_calibration.json`.

## Task 6 — what this changes, and what it does not

**H2 is not supported.** Supplying a genuine, externally-validated, content-bearing biological
target — not an arbitrary magnitude penalty — still does not move the head-carriage defect X1
first documented (§6.10's 0.72–0.76× head deform ratio). If anything, the anterior geometry got
*slightly worse* under the allometric term, though not significantly so.

Per §6's outcome table, this is the **middle row, the decisive negative**: *"proxy holds, head
ratio unmoved [here: moved the wrong way] — narrows the search by ruling out 'shape-plausibility'
as the failure mode entirely. The defect must be something the objective still doesn't reach even
with a semantically correct prior in place."* Two different regularization strategies — a
magnitude barrier (X1) and a validated allometric target (X2) — both fail to move the mechanism,
while both succeed hard on their own proxy. That consistency is itself evidence: the anterior
defect is not a "the model doesn't know what proportions are plausible" problem, it is a
representation/objective-structure problem, exactly the gap G6/G7 already found and fixed with a
joint-*position* term (11.0% vs 38.9% joint residual, a real 34× Pareto trade accepted because the
objective had *no other way* to reach that information). The allometric prior, like the scale cap,
competes for the same gradient budget as Chamfer every step and has no comparable structural
excuse — it can only reshape what the objective already explains, not supply something the
objective structurally cannot see.

**Does not change:** X1's own finding stands untouched. G6/G7's joint-position-term result remains
the one standing positive lead in this record and is *reinforced*, not merely left standing, by
this second independent failure of the "give the model a better shape prior" class of fix.

**Scope:** 50 real scans (`bench50_clean`), matching X1 and the preregistration's primary
comparison. The Atta-only generalization arm (§8) was not run — moot given the primary result is a
clean FAIL, not a corpus-specific null; §8's own logic says a FAIL on `bench50_clean` needs the
Atta-only arm only to distinguish "wrong exponent for this genus mix" from "wrong class of fix,"
and the fact that this term reduces its own residual by 71% with p<1e-9 (i.e. the exponent visibly
does pull specimens toward the reference line, it is not simply inert) argues against "wrong
exponent" and for "wrong class of fix" — but that distinction is not fully closed without the
Atta-only run, which is a candidate follow-up, not required to read this result.
