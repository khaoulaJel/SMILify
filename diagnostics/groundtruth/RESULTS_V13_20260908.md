# V13 — there is no resolvable density curve, and generalisation to unseen landmarks is far
# weaker than V8/V9 indicated. A design error in my own first reading, corrected here.

Job 3854597, 10m24s. Supervise k landmarks, evaluate the 12−k never supervised, k = 2…10, three
independent random draws per k.

## The design error, and why the first table was unreadable

My first output compared each held-out set against the **all-12 production median (10.1%)**. That is
wrong: production error varies **six-fold across landmarks**, so different held-out subsets start
from completely different places.

| landmark | production error |
|---|---:|
| head_width_l | **3.9%** |
| antennal_insertion_r / _l | 4.2 / 4.3% |
| cephalic_post_mid, wl_posterior_r, clypeal_ant_mid | 7.4–7.7% |
| wl_anterior_r, head_width_r | 10.6 / 10.7% |
| mandibular_apex_r / _l | 12.1 / 14.9% |
| **scape_apex_r / _l** | **20.8 / 23.6%** |

Held-out subset baselines in this run ranged **5.8% to 22.2%**. Scored against a single 10.1%
reference, a draw looks good or bad mostly according to which landmarks it happened to hold out.
Every number below is scored against **its own subset's production baseline**.

## The corrected result

| k supervised | median change on UNSEEN landmarks | range across 3 draws |
|---:|---:|---|
| 2 | **−7%** | −8 to −5 |
| 4 | +9% | −19 to +14 |
| 6 | **+25%** | +11 to +31 |
| 8 | **+3%** | **−10 to +28** |
| 10 | +42% | +3 to +60 |

**There is no resolvable curve.** The trend is weakly positive — k=2 makes unseen landmarks slightly
worse, k=6 and k=10 improve them — but the draw-to-draw ranges overlap so heavily that the ordering
is not established. k=8 spans −10% to +28%; k=10 spans +3% to +60%. **At n = 12 specimens with 3
draws per k, this design cannot separate the levels.**

## This substantially weakens V8 and V9's generalisation claim

V9's arm B reported held-out landmark error 13.4% → 7.6%, a **43%** improvement, on one split.
V13 runs the same supervision density (k=8) three more times with different draws and gets a
**median of +3%**, with one draw at **−10%** — worse than production.

V10 had already withdrawn V8's 47% headline as split-dependent. **V13 shows the effect is weaker
still than V10's endpoint analysis suggested**: it is not that supervision reliably drives unseen
landmarks to ~7%, it is that unseen landmarks end up near wherever they started, with a modest and
inconsistent improvement.

> **Sparse surface landmark supervision corrects the points it touches (to 0.1%) and does
> substantially less for the rest than the V-series previously claimed.**

## What this does NOT touch

- **V12's capacity result stands unchanged.** S12 supervises all 12 and measures all 12, so it makes
  no generalisation claim: the model *can* hold every landmark at 0.2% inside its prior. The branch
  point — make the anatomy automatic rather than rebuild the model — is unaffected.
- **V9's two-channel orthogonality stands.** Joints → surface and surface → joints were both null;
  neither depended on generalisation to held-out landmarks.
- **V11's noise floor stands** (2.4% human repeatability).
- **The coverage conclusion is strengthened, not weakened.** G8 found joint supervision needs ~75%
  coverage; V13 finds sparse surface supervision generalises poorly and erratically at every density
  below full. Both channels say the same thing: **anatomical information must be dense.**

## Limits

- 3 draws per k at n = 12 specimens. This is underpowered for the question asked, and the honest
  output is "not resolvable" rather than a curve.
- As k rises the held-out set shrinks (2 landmarks at k=10), so its median is increasingly noisy —
  which is visible as the widening range.
- One λ, one point-to-surface formulation, one run per draw.
- **A properly powered version** would need more specimens, more draws, and per-landmark rather than
  per-subset scoring. Whether that is worth running depends on whether the density question still
  matters once anatomy is supplied automatically — at which point coverage is a property of the
  predictor, not a design choice.
