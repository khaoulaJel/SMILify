1. THE E6/E7 METHODOLOGY — GROUND TRUTH, "CORRECT", AND WITHIN- VS BETWEEN-PART
================================================================================

1.1 How ground-truth correspondence is defined (E6)

File: diagnostics/moonshot/make_synth_corpus.py

Targets are NOT scans. They are generated FROM the model itself:
  - SMAL3DFitter with random pose (pose_scale 0.25), shape (shape_scale 1.0),
    per-joint log-scale (sd 0.10), NO global rotation (canonical alignment kept,
    matching how real scans are pre-aligned), NO translation.
  - `verts = fitter()` gives (n_specimens, V, 3). Vertex i of specimen s IS, by
    construction, the anatomical point "vertex i of the template" — there is no
    labeling step, no annotation, no proxy. This is what makes it a true ground
    truth rather than a population-consistency proxy (which is all probe-19 ever
    gave the branch before E6 existed).
  - Two corpora: synth_clean (noise=0), synth_noisy (per-vertex Gaussian, sd =
    0.25% of extent, chosen to bracket real worker roughness: worker median
    dihedral 10.54 deg / edge-CV 0.43 vs the reference corpus's 8.20 deg / 0.30).
  - 12 specimens each, seed 20260806.
  - This is explicitly a CEILING test: no debris, no holes, no preservation
    artefacts, exact target geometry. "If the pipeline cannot establish
    correspondence here, it cannot on ethanol-preserved worker scans."

1.2 How "correct" is scored (E6)

File: diagnostics/moonshot/score_synth_roundtrip.py

  - The fitted mesh and the ground-truth mesh are put in the SAME frame (the
    frame fitter_3d/utils.py::load_meshes actually uses: centre, divide by
    max|coord|), derived from the EXPORTED (possibly noisy) mesh, since that is
    what the fitter actually saw. Scoring itself is against the CLEAN ground
    truth (crediting a fit for reproducing injected noise would measure the
    wrong thing).
  - For every fitted vertex f_i: `nn = knn_points(f_i, ground_truth, K=1)`.
    "Correct" := nn's index == i (the fitted vertex's nearest ground-truth
    neighbour is its OWN ground-truth point). This is a strict, symmetric,
    per-vertex definition — not a tolerance/threshold metric.
  - Headline result (12 specimens, 10229 verts each -> 122,748-ish vertex-events,
    exact count 122,820 appears in the gt7/gt16 JSONs which pool identically):
        SYN_clean : 4.81% correct, median error 3.48% of extent, p90 19.18%
        SYN_noisy : 4.18% correct, median error 3.57% of extent
  - Calibration control: isotropic noise of the SAME magnitude (3.48% of
    extent) scores 3.03% "correct" under the identical metric — i.e. the fit's
    4.81% is barely above what pure noise achieves at that error magnitude. The
    branch's own honest headline is therefore "~3.8 vertex-spacings of error",
    not "4.81% correct" read at face value.
  - Per-part breakdown in this report uses an AD HOC 7-way split defined by
    `part_of()` inside score_synth_roundtrip.py itself: thorax / gaster / head /
    mandible / antenna / "leg prox" (coxa+trochanter+femur, POOLED across all 6
    legs and both sides) / "leg distal" (tibia+tarsus+pretarsus, same pooling).
    This is a DIFFERENT grouping from the one used for the 83.3% ceiling number
    (next section) — same group count (7) by coincidence, different partition.
    Worst part here: gaster, 1.5% correct, 10.41% median error (a large, smooth,
    nearly featureless ellipsoid — chamfer has almost no positional information
    on it, so many correspondences give identical surface error). Legs are
    AMONG THE BEST parts (leg prox 6.3% correct), which the report flags as
    "the opposite of what thin-structure reasoning predicts."

1.3 How "within-part" vs "between-part" is defined (E7 — this is the 83.3% source)

File: diagnostics/moonshot/hull/why_partitions_null.py
Output JSONs: diagnostics/moonshot/hull/out/error_split_gt7.json,
              diagnostics/moonshot/hull/out/error_split_gt16.json

  - Part labels come from `fitter_3d/trainer_hierarchical.py::anatomical_groups()`,
    NOT from score_synth_roundtrip.py's ad hoc part_of(). This is the SAME
    grouping function used to drive the actual hierarchical fitter's per-part
    data term, so it is the most "load-bearing" definition in the codebase —
    but it has two granularity switches:
        gt_groups="7"  : split_distal=False, split_anterior=False
            -> "body" (thorax+gaster+head+mandible+antenna ALL MERGED) + 6 leg
               groups (split by leg-index AND side, e.g. l_2_r vs l_2_l, but
               NOT split into proximal/distal). 1 + 6 = 7 groups.
        gt_groups="16" : split_distal=True, split_anterior=True
            -> head, mandible, antenna each get their own group; "body" is left
               with only thorax+gaster; each of the 6 legs is split into
               proximal (coxa/trochanter/femur) and distal (tibia/tarsus/
               pretarsus) halves -> 12 leg groups. 3 + 1 + 12 = 16 groups.
    IMPORTANT ASYMMETRY: at gt7 (the grouping the 83.3% headline uses), the
    entire anterior region — head, mandible, antenna, exactly what an
    SDF-based part mask would most plausibly target — is COLLAPSED into one
    undifferentiated "body" blob together with the thorax and gaster. Legs, by
    contrast, ARE already separated per-instance-and-side at gt7. So gt7 is
    coarser than "the rig's own granularity" specifically in the anterior
    region, and about as fine as the rig gets for legs (short of segment-level
    splitting).
  - Per fitted vertex: `nn` = nearest ground-truth vertex (as in E6).
        correct  := nn == own index
        landed_part := part label of the ground-truth vertex nn landed on
        own_part    := part label of the vertex's own (correct) identity
        between  := (not correct) AND (landed_part != own_part)
        within   := (not correct) AND (landed_part == own_part)
  - Logic: "A partition can only fix errors that CROSS a part boundary. It is
    structurally incapable of fixing an error INSIDE a part, because every
    candidate landing site there carries the same label and the data term is
    therefore identical." This is definitionally true for ANY masking/gating
    mechanism that operates by restricting candidate correspondences to
    same-label points — including SDF-derived labels, which is exactly the
    mechanism the SDF-guided brief proposes.

1.4 The actual numbers at both granularities (from the JSONs directly)

    run=SYN_clean, n_vertices=122820 for both:

                                gt7 (7 groups)      gt16 (16 groups)
    exactly correct              4.81%                4.81%
    WITHIN-part error            83.34%               79.15%   <- ceiling-setting
    BETWEEN-part error           11.84%               16.04%   <- addressable set
    median err, within-part      3.32% of extent       3.25%
    median err, between-part     21.08% of extent      13.72%
    ceiling for a PERFECT
      partition (correct+between)  16.66%               20.85%

    Source of the "head only 6.9% between-part" and "distal first legs 47%
    between-part" figures: diagnostics/moonshot/hull/REPORT_HULL.md, section 5.

1.5 DIRECT ANSWER to "does granularity inflate or deflate 83.3%?"

  - Going from the coarser grouping (gt7, which merges the entire anterior
    region into one blob) to the finer one (gt16, which separates head /
    mandible / antenna from each other and splits every leg into proximal/
    distal) moves the ceiling from 16.66% to 20.85% — a ~4 percentage point
    swing, not a qualitative change. Within-part error stays the dominant term
    (79-83%) at both granularities.
  - gt16 is still coarser than "the rig's own granularity" in one respect not
    tested here: it does not split legs into individual segments (coxa vs
    trochanter vs femur vs tibia vs tarsus vs pretarsus) — the raw joint-ID
    granularity the new brief's Phase C1 worries about. That finer split was
    NOT measured on this branch; I did not find a gt-more-than-16 run. This is
    a genuine gap, not something to silently round up or down.
  - However, note what SDF ACTUALLY achieves as a partition (section 3 below):
    it recovers 5 of 6 leg instances cleanly but MERGES the front leg pair
    (left/right), i.e. in practice SDF-derived labels land at CLOSER TO gt7
    granularity than gt16 for legs, and would need extra work (the report
    suggests a bilateral-symmetry prior) to even reach gt7's leg resolution.
    For the anterior region, SDF separates head/leg/antenna well (AUC 0.97-
    0.99) but the probe never measured whether it can separate head FROM
    mandible FROM antenna at gt16 resolution — only body-vs-appendage and
    gaster-vs-leg were scored.
  - Net honest reading: the 83.3% number is computed at a granularity that is
    IF ANYTHING coarser than what SDF masking could achieve in the legs, and
    UNTESTED (neither confirmed nor refuted) at finer-than-gt16 leg-segment
    resolution. The finer measurement that exists (gt16) still leaves the
    within-part term dominant (79.15%), so the conclusion looks robust to this
    specific granularity choice, but "robust up to gt16, untested beyond it" is
    the precise, defensible statement — not "robust at every possible
    granularity."

2.1 Offset penalty (w_offset)

Code (trainer_moonshot.py, Stage.forward-equivalent):

    if lw.get("w_offset", 0.0) > 0:
        l_o = self.smal_3d_fitter.deform_verts.pow(2).sum(-1).mean()
        comp["offset"] = l_o
        loss = loss + lw["w_offset"] * l_o

  - Plain L2 penalty on free-form per-vertex offsets (deform_verts). Nothing
    bounds this quantity in stock trainer.py at all.
  - Production weight (D1_low.yaml, confirmed by `git show ...:diagnostics/
    moonshot/cfg/D1_low.yaml`): w_offset: 5.0 in the first stage, w_offset: 2.0
    in the second. FINAL_REPORT's "25x" framing refers to this relative to some
    earlier baseline weight, not a tuned optimum.
  - Status per FINAL_REPORT §6.2: "25x was a round number; the optimum is known
    to be interior [not monotonic] and the instrument [E6] exists. One
    afternoon [of sweep work]." The recommended sweep (w_offset in {2.0/0.8,
    5.0/2.0, 10/4, 20/8} on synth_clean, scored by E6) has NOT been run — I
    found no output file for it (`runs/` has no matching directory names, and
    no OFFSET_SWEEP-style report exists on the branch).
  - MERGE-READINESS: implementation is self-contained (one config-gated `if`
    block, no dependency on other moonshot-only machinery) and IS the single
    largest measured correctness gain in the whole investigation (4.81% ->
    6.69%, +39% relative, on E6). But it is being ported at an untuned weight.
    Recommend running the sweep before/immediately after porting, not treating
    5.0/2.0 as final.

2.2 Rest-edge loss (edge_mode)

Code (trainer_moonshot.py):

    def rest_edge_loss(pred_verts, rest_verts, faces):
        e = torch.cat([faces[:, [0,1]], faces[:, [1,2]], faces[:, [2,0]]], dim=0)
        l0 = (rest_verts[:, e[:,0]] - rest_verts[:, e[:,1]]).norm(dim=-1)
        l1 = (pred_verts[:, e[:,0]] - pred_verts[:, e[:,1]]).norm(dim=-1)
        return ((l1 / (l0 + 1e-9)) - 1.0).pow(2).mean()

    # in Stage.forward-equivalent:
    if self.edge_mode == "shrink":
        # stock behaviour kept ONLY for a control arm: mesh_edge_loss(target_length=0)
        # actively shrinks the mesh, kept commented as a known stock defect.
        l_e = mesh_edge_loss(src_mesh)
    else:
        with torch.no_grad():
            rest_now = self.smal_3d_fitter(deform_verts=torch.zeros_like(...)).detach()
        l_e = rest_edge_loss(src_mesh.verts_padded(), rest_now, self.faces[0])

  - Critical semantic point documented in the code itself: `rest_verts` MUST be
    the model's CURRENT pose/shape with deform_verts zeroed (recomputed live),
    NOT the original template. An earlier version of this code compared
    against the original template and it penalised legitimate pose/shape
    change (per-joint scaling alone reaches ~2.6x), driving the term to 3.53
    against chamfer's 0.005 — a ~35x-oversized regulariser that silently
    turned the run into "stay near the template". This was found and fixed
    on-branch; anyone porting this must port the CORRECTED version (uses
    `rest_now`, recomputed with `torch.no_grad()`), not re-derive it from the
    docstring description alone.
  - Validated in isolation: with the corrected reference, an articulated-but-
    undeformed mesh scores exactly 0.

  - MERGE-READINESS — IMPORTANT CAVEAT NOT TO MISS:
    I confirmed directly in diagnostics/moonshot/cfg/D1_low.yaml:
        edge_mode: shrink      (both stages)
    i.e. the ACTUAL recipe (D1) that produced every reported number in
    FINAL_REPORT still uses the OLD shrinking edge loss, NOT rest_edge_loss.
    FINAL_REPORT §1 flags this explicitly as one of "two production-config
    defects to fix before using [D1] as a baseline" and §2.2 row 4 says
    porting `rest` "needs one confirmation run" — meaning the reported D1
    numbers do NOT reflect this fix being active. This is the less
    merge-ready of the two items: correct in isolation, implemented, but
    never actually exercised in the pipeline that generated the headline
    results. Do not assume it's already "in" D1's measured gains.

3. SDF PROBE (diagnostics/moonshot/sdf_prior_PROBE.py) AND THE bench50_clean CORPUS
================================================================================

3.1 What the SDF probe actually measured

File: diagnostics/moonshot/sdf_prior_PROBE.py (178 lines)
Output: diagnostics/moonshot/sdf_prior_out.txt
Commit: 0ed9243 "proxy probes: volume-IoU adjudicated against chamfer; SDF part
        prior gated out"

Method: CGAL-style Shape Diameter Function. For each surface point with normal
n: cast `n_rays=25` rays into a cone of half-angle 60 deg (`cone_deg=120.0`
total) about -n, using `trimesh.ray.ray_pyembree.RayMeshIntersector` (embree,
already in the pytorch3d env — no new dependency). Take first-hit ray lengths,
reject outliers beyond 1 std of the median, mean the rest. NaN where <3 valid
rays. No smoothing/normalisation beyond dividing by mesh scale (bbox diagonal)
for cross-mesh comparability.

Gates (borrowed verbatim from diagnostics/moonshot/hull/eval_decomposition.py,
so results are comparable across every partition method tried on this branch):
    G1 REPRODUCIBILITY: two independent surface samplings (4000 pts each) must
       agree >= 90% (this probe measured Pearson r, median relative diff, and
       a simpler "thick vs thin" 2-way threshold-agreement stat).
    G4 COST: < 60 s/specimen on CPU.

Results (from sdf_prior_out.txt, verified verbatim):
  - Template (SMIL_OmniAnt.pkl, 10229v/20454f, watertight, 1 component):
      SDF computed in 0.7s, nan_frac 0.0007.
      By anatomical group (SDF/scale): gaster p50=0.0844, thorax p50=0.0635,
      head p50=0.0838, leg p50=0.0111, antenna p50=0.0023 — legs and antennae
      are an order of magnitude thinner than body parts, as expected.
      gaster-vs-leg AUC = 0.9948 (best balanced acc 96.91% @ one global
      threshold sdf/scale=0.0294).
      body-vs-appendage AUC = 0.9730 (best balanced acc 95.11% @ threshold
      0.0307).
      Leg INSTANCE recovery (threshold at 0.0307*scale, connected components
      of the "thin" side): 5 of 6 leg instances recovered PURE (purity 1.00);
      the 6th failure is the front leg pair (l_1_r + l_1_l) MERGING into one
      component (purity 0.50) — a laterality confusion, not a body/appendage
      failure. Head appendages (antennae/mandibles) l/r pairs: purity 0.98-1.00.
  - Real scans (bench50, first 6 alphabetically, real ethanol-preserved CT
    scans, NOT watertight, 621-5521 connected components each): G1 agreement
    87.8-95.2% (median ~93%) across the 6 scans shown, all well above the 90%
    gate on most, and far above the geodesic-branch method's measured 20% on
    the same gate. Cost 0.6-1.2s/specimen, far under the 60s G4 budget, using
    only trimesh 4.4.3 + embreex 4.4.0.

CONCLUSION line from the probe's own output: "SDF passes G1 (>=87.8%, median
~93% vs geodesic's 20%) and G4 (<1.3s vs 60s budget) on real ethanol scans
with 621-5521 connected components and no watertightness."

3.2 Why it was still "gated out" despite passing

SDF passing G1/G4 establishes it is a reproducible, cheap, anatomically
sensible PARTITION SIGNAL — exactly like the convexity-hull decomposition,
which also passed reproducibility (0.94-0.99) and was ALSO gated out. Neither
was killed for being an unreliable signal. Both were killed by the
GRANULARITY-INDEPENDENT ceiling established in section 1 above: 79-83% of
correspondence error never crosses ANY part boundary, so no partition method,
however good its G1/G4 scores, can move correspondence past ~17-21%. The SDF
probe was the LAST partition candidate tried (same commit as the final
volumetric-IoU adjudication, immediately before the final report was written)
— it was evaluated against this same ceiling logic rather than run through
the full fitter pipeline, because the pre-registered kill condition (the same
one used for the convexity-hull "chunk vote never beats the incumbent" result)
already applied by construction: SDF labels are still a partition, and the
ceiling bounds partitions regardless of which algorithm produces them.

3.3 bench50_clean — provenance and how to reuse it

  - The `diagnostics/moonshot/bench50_clean/` directory already staged in this
    session's git status (50 files) is BYTE-IDENTICAL in filename listing to
    the same path on upstream/feature/registration_moonshot (diffed directly,
    zero differences). This is the branch's own benchmark corpus, not a
    coincidentally-named new set.
  - Provenance: `bench50` is the branch's standing 50-specimen working corpus
    (real CASENT/OKENT-accessioned ethanol-preserved ant CT scans), used
    throughout REPORT.md for the `radial_med` fittability-gate discovery
    (bench50, n=50, Spearman rho +0.81 vs chamfer_l2) and cross-checked against
    two DISJOINT 50-specimen held-out sets (`easy`, `rand`) drawn from a larger
    707-specimen pool — bench50 itself was never described as randomly drawn;
    treat it as the branch's fixed dev/working set, not a held-out set, if
    reusing it for anything that claims generalization.
  - `bench50_clean` = bench50 run through diagnostics/moonshot/preprocess_meshes.py
    (component-drop by area threshold, duplicate-vertex merge, small-hole fill,
    volume-preserving Taubin smoothing; isotropic remeshing OFF by default).
    Measured effect of this cleaning (REPORT.md §6, 50 specimens): vertex
    components 44.5->4.0 (reference corpus: 3.0), boundary edges 0.0554->
    0.0302 (ref 0.0388), non-manifold edges 0.0365->0.0053 (ref 0.0709 — i.e.
    cleaned bench50 is BETTER than the reference on this axis), triangle
    quality 0.8336->0.8603 (ref 0.8635), median dihedral 10.70->8.27 deg (ref
    8.20), edge-length CV 0.4709->0.4294 (ref 0.3000, still the largest
    residual gap).
  - IMPORTANT — this cleaning was tested and found NOT to help registration:
    REPORT.md §6.1, "mesh preprocessing is not what prevents these scans from
    being fitted." Cleaning made the SCORING TARGET easier (surface metrics
    improved) while making registration marginally WORSE on every
    target-independent metric (deform_mag, edge_logratio, midline_dev — no
    row in the reported table showed a real improvement, several ns or
    slightly negative). Scored on surface metrics alone this would have read
    as a 6.6% win; scored honestly it is a null-to-negative result. So: reuse
    bench50_clean for COMPARABILITY (same specimens, same cleaning state as
    every prior probe on this branch), not because cleaning was proven to
    help — it wasn't, and re-discovering that would waste a cycle.
  - Corpus for direct correspondence ground truth is SEPARATE from bench50:
    diagnostics/moonshot/synth_clean/ and synth_noisy/ (12 model-generated
    specimens each, ground_truth.npz per corpus) — this is what E6/E7 actually
    scored against, not bench50. bench50(_clean) has no ground-truth
    correspondence and cannot be used for a "% correct" style metric directly;
    it's for surface/integrity metrics and the fittability-gate work.
  - Practical reuse recommendation for new diagnostics: point any new SDF/
    partition probe at diagnostics/moonshot/bench50_clean/*.obj (matches every
    prior real-scan probe on this branch) for the "does this look sane on
    real scans" check, and at diagnostics/moonshot/synth_clean/ +
    score_synth_roundtrip.py's scoring protocol for any "is this actually
    correct" check — do not build a new synthetic ground-truth generator, the
    existing one (make_synth_corpus.py) is deterministic (fixed seed) and
    already the thing every number in this note is anchored to.
