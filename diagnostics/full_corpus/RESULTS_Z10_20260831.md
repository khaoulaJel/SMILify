# Z10 — 1-NN understated the signal by ~44%. The conclusion does not change.

757 worker production fits, lot-blind leave-one-LOT-out, each model against **its own**
permutation null (a stronger model has a higher chance baseline, so borrowing 1-NN's null would
manufacture a win). Zero new fitting.

## Result

| feature set | model | accuracy | null | lift |
|---|---|---:|---:|---:|
| **R ≥ 0.1 (45 traits)** | 1-NN (Z9 baseline) | 0.113 | 0.022 | 5.17× |
| | LDA (shrinkage) | 0.145 | 0.024 | 5.98× |
| | **logistic L2** | **0.163** | 0.023 | **7.21×** |
| all traits (71) | 1-NN | 0.091 | 0.022 | 4.20× |
| | LDA (shrinkage) | 0.138 | 0.026 | 5.24× |
| | logistic L2 | 0.150 | 0.025 | 6.00× |

**The classifier was part of the limit.** Logistic L2 reaches 16.3% against 1-NN's 11.3% — a
**+44% relative improvement**, lift 5.17× → 7.21×. `analyse.py` chose 1-NN honestly for a corpus of
60–150 specimens; at 757 it understates what is there.

**Z9's feature-set finding replicates under every model.** R ≥ 0.1 beats all-71 for 1-NN
(0.113 vs 0.091), LDA (0.145 vs 0.138) and logistic (0.163 vs 0.150). The mild reliability filter
is right, and it is not an artifact of the weak classifier.

## My pre-registered decision rule failed, and the script's verdict should be ignored

The rule was "≥ +0.05 absolute accuracy → the classifier was the limit". The measured gain is
**0.049834**. The script printed *"THE MEASUREMENT IS THE LIMIT"* on a margin of 0.000166 — a
floating-point knife-edge, not a finding. **That printed verdict is meaningless and is retracted.**

The rule was badly designed, and the failure is more interesting than the arithmetic: a single
threshold on absolute accuracy gain cannot express the actual situation, which is that **both
things are true at once.** The classifier was understating by 44% relative, *and* the absolute
level remains far too low to use. A binary rule forced a choice between two statements that are
both correct.

## The number that decides usability, recomputed under the best model

| | 1-NN | **logistic L2** |
|---|---:|---:|
| conspecific pairs (lot-blind) | 318 | 318 |
| **nest-mates assigned the same genus** | 5.7% | **10.7%** |
| chance | 3.0% | 3.8% |
| lift | 1.89× | **2.82×** |
| **both correct** | 1.9% | **5.7%** |

Every figure roughly doubles — and **10.7% agreement is still not a usable per-specimen method.**
Two workers from one colony receive different genus assignments nine times in ten.

## Standing conclusion, unchanged in substance and sharper in number

- **The genus signal is real**: 7.21× lift, lot-blind, on 83 genera, with the null recomputed per
  model. Stronger than previously measured.
- **It remains population-level only**: 16.3% accuracy, 10.7% nest-mate agreement.
- **Report** the pooled effect with its lift and its null, on the R ≥ 0.1 feature set, using a
  regularised linear classifier rather than 1-NN.
- **Do not report** per-specimen genus assignments, or any claim whose unit is one specimen.
- **Attach conspecific agreement** to any classification claim. Accuracy alone hides the fact that
  the method disagrees with itself on nest-mates.

## What is now closed

Z6 showed the registration is at its noise floor. Z8 showed no trait is individually repeatable
(median R 0.149). Z9 and Z10 show the classifier built on them recovers a real but small pooled
signal, and that a stronger classifier lifts it by 44% relative without changing what it can be
used for.

The remaining headroom is in the classifier and the feature set, not the fitter — and it is
bounded: going from the weakest honest classifier to a well-regularised one bought 5 accuracy
points. Nothing in Z1–Z10 suggests the fitter has more to give.
